# Project Lock

The Project Lock is the strategy contract for one landing page. It is written before implementation and remains stable unless new evidence materially changes the brief.

```md
# PROJECT LOCK

## Page state
Greenfield | Brownfield

## Desired outcome
<measurable or observable result>

## Target visitor
<who they are, awareness state, entry trigger/source>

## Product / offer truth
<what exists today and what can honestly be demonstrated>

## Primary CTA
<label>

## CTA destination / success state
<what happens immediately after click or submit>

## Belief gap
<what the visitor must understand or believe before acting>

## Primary objection
<largest friction, risk, distrust, or confusion>

## Evidence available
<verified proof assets>

## Missing proof
<what cannot currently be substantiated>

## Protected assets
<brand, product behavior, copy, data, routes, integrations, design-system constraints>

## Technical constraints
<stack, hosting, forms, analytics, performance, accessibility, legal, integrations>

## Success measure
<metric or observable condition>

## Failure conditions
<what makes this page fail regardless of visual quality>
```

## Change control

A builder may not silently weaken the Project Lock to make implementation easier. If new evidence changes the outcome, CTA, product truth, or protected constraints, record the change and why it is justified before continuing.
