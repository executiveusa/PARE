# The Art of Reduction
Version 1.0.0 — PARÉ workflow edition

## Purpose
Make the human's task easier without deleting what makes the work true, useful, distinctive, or safe.

**Full understanding → essential meaning → natural expression → smallest useful presentation → verified result.**

This is an editing and design workflow, not a visual style. It does **not** mean white space, minimalism, monochrome, giant type, sparse layouts, or any inherited aesthetic. The minimum is the point at which another removal would damage the intended outcome.

## PARÉ workflow law
For substantial product, website, UX, copy, workflow, or brownfield simplification work, run this skill after project truth/constraints are established and before implementation is approved.

Required sequence:
1. Inspect the real source and rendered state.
2. Lock outcome, human, constraints, protected assets, evidence, rollback, and commercial value.
3. Define the project's own visual world before visual design.
4. Inventory content/components using KEEP / REPOSITION / REWRITE / REPLACE WITH EVIDENCE / REMOVE / MISSING.
5. Reduce only what does not damage task completion, identity, trust, accessibility, evidence, or owner control.
6. Implement one reversible bounded slice.
7. Verify the rendered result at relevant breakpoints and reduced-motion state.
8. Stop when another subtraction would make the human less successful.

**Permanent design law:** Preserve standards. Forget style. Every brand earns its own world.

Never use prior PARÉ projects, portfolio aesthetics, Collins, Apple, Awwwards, Impeccable, Steve Krug, or other references as visual templates. They are quality/process benchmarks only.

## 1. Inspect before editing
Read the actual material, surrounding context, owner instructions, source, rendered experience, assets, content, tests, and relevant project constitution.

Record:
- **Object:** target, source path/version, format.
- **Human:** audience, task, device, language, situation.
- **Outcome:** what the person must understand, decide, or accomplish.
- **Protected:** approved words, brand, mechanics, functionality, facts, accessibility, legal requirements, ownership, rollback.
- **Evidence:** source material, measurements, screenshots, author samples, test results, unknowns.
- **Visual World:** Emotional Target, Cultural Sources, Typography, Color Behavior, Density, Composition, Image Language, Motion Language, Anti-References.

For unrelated brands, reject any direction that resembles another portfolio project with only copy, logo, color, or imagery changed.

### Provenance is not an AI detector
Separate human-written and AI-written material only when authorship is known from source, revision history, or the owner. Otherwise mark origin unknown. Never invent authorship probabilities.

## 2. Choose the right editor
Use only the relevant branch:
- copy: Humanizer + Stop Slop principles;
- plans/instructions: ADHD Elegant Simplicity;
- websites/interfaces: Collins process + ADHD + actual visual references when needed;
- brand: strategy and brand-world definition before styling;
- code/workflow: inspect/reuse/native-first/smallest working diff.

### Non-negotiable boundaries
Never remove required facts, uncertainty, citations, safety instructions, accessibility, error recovery, validation, consent, approval gates, legal obligations, proof, rollback, or owner control merely to shorten the work.

## 3. Run the reduction scale
These are editorial levels, not a clinical score.

- **R0 — Source:** complete original material, evidence, constraints.
- **R1 — Essential:** remove duplication and unrelated detail.
- **R2 — Human:** specific, natural language; preserve voice and facts.
- **R3 — Composed:** one dominant idea per screen/state; clear hierarchy and action.
- **R4 — Minimum useful:** remove anything else only if meaning, completion, identity, trust, proof, and accessibility survive.

R4 is not always the target.

### Subtraction loop
For each element ask:
- Does it need to exist?
- Can it be removed, combined, reused, inferred, remembered, prepared, or disclosed only when needed?
- Does it add a fact, aid a decision, express real identity, provide evidence, or support an action?
- Is this element here because this brand needs it, or because another project used it?

For code, prefer existing implementation, platform primitives, and installed dependencies. Fix root causes. Do not code-golf away maintainability or checks.

## 4. Show the edit before applying it
Use:
- **KEEP VERBATIM**
- **KEEP AND REPOSITION**
- **REWRITE WITH APPROVAL**
- **REPLACE WITH EVIDENCE**
- **REMOVE**
- **MISSING AND REQUIRED**

Preserve a complete audit trail outside the reduced client presentation.

## 5. Verify and stop
Review source and result side by side. Check:
- Meaning
- Clarity
- Humanity
- Economy
- Fit
- Brand distinctiveness
- Accessibility
- Responsive behavior
- Reduced motion
- Primary action
- Proof integrity

A successful build is not proof of a usable product.

For substantial visual work, rendered browser evidence is required before merge. Builders do not approve themselves; use an independent review/gate where available.

**Stop when nothing else can be removed without making the human less successful.**
