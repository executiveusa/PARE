# ZTE-20260902-0002 — PARÉ Studio consolidation

## Objective
Turn the existing `executiveusa/PAULI-open-design` fork into the canonical PARÉ human + agent studio without rebuilding Open Design's existing web/daemon/CLI/MCP surfaces and without making ICM a runtime dependency.

## Baseline
- Canonical implementation repo for this slice: `executiveusa/PAULI-open-design`.
- Upstream: `nexu-io/open-design` (Apache-2.0). Preserve upstream license/notices and keep the fork updateable.
- Legacy/migration source: `executiveusa/brand-kit-builder-`.
- Interaction reference only: `executiveusa/pauli-open-codesign`.
- ICM method source: uploaded `icm-architect` bundle (MIT), implemented as file/folder conventions + skills, not as a new framework package.
- Ponytail rule: reuse repository/platform/native capability before adding code or dependencies.

## Product decision
Open Design remains the interaction/runtime base:
- Next.js web Studio;
- chat + artifact canvas + comments + files + live run stream;
- daemon as privileged long-running runtime;
- existing agent CLI adapters;
- existing `od` CLI, HTTP `/api/*`, and MCP capability;
- existing artifact/export pipeline.

PARÉ adds only the missing house layer:
- PARÉ identity/brand surface;
- One Hands orchestration policy;
- ICM project structure and cold-start routing;
- Pauli brand strategy / creative-direction / validation skills;
- Guardian/Gauntlet/Proof gates;
- optional authentication and multi-user policy where the existing runtime does not already provide it;
- owner-controlled deployment topology.

## Deployment topology
### Today / owner-operable target
`browser/phone -> Vercel web -> authenticated HTTPS -> PARÉ daemon on owner VPS -> agent CLIs + ICM project filesystem`

Vercel is presentation/SSR only. The daemon does not belong on Vercel serverless because it is long-running, owns filesystem state, streams runs, and spawns agent CLIs.

### Local fallback
`browser/desktop -> local web -> local daemon -> local agent CLIs`

### Direct API fallback
Keep upstream browser-only/BYOK mode as a degraded trial path; it is not canonical for sovereign PARÉ projects.

## ICM model
ICM is a filesystem contract. No ICM npm package, database SDK, orchestration framework, or duplicate state engine.

A canonical PARÉ project is folder-backed and uses:

```text
<project-root>/
├── AGENTS.md
├── CONTEXT.md
├── 00_intake/
├── 10_strategy/
├── 20_design/
├── 30_validate/
├── 40_deliver/
├── 50_publish/
└── _ledger/
```

Every working stage owns a small `CONTEXT.md` naming exact inputs, process, outputs, and human gate. Stable rules live in `_shared/` / `_system/`; run artifacts live in stage folders. One home per fact.

Open Design's project/workspace is a view over this folder, not a second source of project truth.

## Consolidation map
### Reuse from Open Design; do not duplicate
- web shell, chat, canvas, files, preview, comments, run streaming;
- project model and folder-backed workspaces;
- daemon lifecycle and data-root contract;
- agent detection/adapters;
- contracts package;
- `/api/*` boundary;
- `od` CLI;
- MCP server/tooling;
- skill registry;
- design-system registry;
- artifact/export pipelines;
- desktop/packaged shells;
- observability already present upstream.

### Port from Brand Kit Builder as files/skills/contracts only
- One Hands policy;
- ICM stage/gate vocabulary where compatible with the uploaded ICM method;
- creative-direction laws;
- Design Guardian;
- Gauntlet;
- Proof/completion gates;
- humanize/subtraction/SEO/SVG skills;
- PARÉ brand manifest/design system;
- governed publishing rules and Postiz integration only if no upstream equivalent exists.

### Do not port
- old Vite marketing app;
- duplicate REST/MCP/CLI runtimes;
- duplicate workflow runtime where Open Design already owns execution;
- duplicate project/session/artifact state;
- provider-specific agent framework as canonical truth;
- Vercel-specific filesystem state.

## Work slices
### A — pristine baseline
1. Keep `main` unchanged until the original fork has a working Vercel web baseline.
2. Verify actual home/workspace UI, build status, routes, and runtime boundary.
3. Record baseline screenshots/behavior before PARÉ branding.

### B — ICM + One Hands
1. Add ICM Architect as a normal file skill with license provenance.
2. Add One Hands as the PARÉ orchestration skill/prompt layer.
3. Add a PARÉ project initializer that creates only the smallest ICM tree needed for a new project.
4. Map Open Design project cwd/baseDir to the ICM root; do not create parallel storage.
5. Ensure One Hands routes skills but does not own brand truth.

### C — PARÉ product surface
1. Rebrand the fork's product-facing shell to PARÉ while preserving Apache-2.0 notices.
2. Keep the existing Home -> project/workspace interaction model.
3. Primary human flow: enter/open project -> chat with One Hands -> live artifact -> inspect/comment -> Guardian/Gauntlet -> approve/export.
4. Hide provider/runtime machinery behind progressive disclosure.
5. Keep Open Design upstream naming only where required for attribution/technical compatibility.

### D — universal agent access
1. Reuse `od` CLI + existing MCP + HTTP API.
2. Close any missing machine surfaces using the upstream rule: endpoint + UI + CLI in the same change.
3. External agents operate on semantic project/work-order/artifact operations, never React state.
4. Machine writes are candidate artifacts until validation/approval gates advance them.

### E — VPS execution plane
1. Run daemon as a long-lived service on owner-controlled VPS.
2. Persistent volume for daemon data + folder-backed ICM projects.
3. HTTPS reverse proxy with SSE buffering disabled.
4. Authentication at the daemon edge; never expose an unauthenticated agent-spawning daemon publicly.
5. Install only approved CLI adapters/credentials server-side.
6. Health, logs, restart policy, backup, rollback.

### F — optional human accounts
Prefer existing Open Design account/workspace capability if it satisfies the requirement. Only if a real gap remains, adapt the existing Brand Studio Supabase Auth/RLS domain; do not introduce a second auth system preemptively.

## Rollback
- Branch is isolated from `main` until verification.
- Every PARÉ customization stays in small commits so it can be reverted independently.
- Upstream fork ancestry remains intact; no history rewrite.
- Web preview rollback = previous Vercel deployment.
- VPS rollback = previous container/service image + persistent project volume preserved.
- ICM migration is additive/copy-first until walk-test passes; do not delete legacy brand-kit files during this slice.

## Risk
MEDIUM for branch work and preview deployment.
HIGH only when exposing the agent-spawning daemon publicly or migrating production project truth; those actions require a separate security gate.

## Definition of done for this slice
A user can open the PARÉ web Studio from phone/desktop, enter an ICM-backed project, talk to One Hands, run an approved agent engine, watch artifacts appear in the existing canvas, inspect/comment on the result, and access the same project through machine interfaces without maintaining a parallel project architecture.
